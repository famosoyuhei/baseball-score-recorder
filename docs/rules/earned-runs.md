# 自責点メモリ

## 基本方針

自責点は、投手責任とは別に判定する。

責任投手は「誰の走者か」を示し、自責点は「その得点が投手に自責として課されるか」を示す。

## 監査で分けるもの

- 走者の責任投手
- 走者の自責点候補状態
- 失策や捕逸がなければ得点していたか
- イニングが本来終了していたか

## 壊れやすいケース

### 失策で出塁した走者

原則として、その走者の得点は非自責点候補になる。

ただし、その後のプレー展開によって判断が必要になるため、アプリ仕様としてどの粒度まで追跡するかを確認する。

### 2アウト後の失策

本来なら3アウトでイニング終了していた場合、その後の得点は非自責点候補になる。

### 捕逸

捕逸による進塁・得点は自責点から除外される可能性がある。

### 暴投

暴投は投手責任のイベントであり、自責点判定に含まれる可能性がある。

### 投手交代後

得点した走者の責任投手と、その得点の自責点扱いを分けて確認する。

## アプリ監査観点

- `runnersEarnedStatus` が塁移動に追従する
- 走者アウト時に対応する自責点状態が削除される
- 槽交替時に必要な状態が引き継がれる
- 保存復元後も自責点状態が保持される
