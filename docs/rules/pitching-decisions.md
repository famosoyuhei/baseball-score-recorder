## 基本方針

勝敗投手・セーブ・ホールドは、投手の失点責任や自責点とは別の記録である。

アプリでは次の2段階で扱う。

1. ルール上の自動候補を算出する
2. 記録員判断が必要な場合は候補と理由を表示し、人間が確定する

## 勝投手

### 原則

自チームがその投手の任務中、またはその投手が代打者・代走者と交代して退いた攻撃回にリードを奪い、そのリードを最後まで保った場合、その投手が勝投手候補となる。

同点になった時点で、勝投手の判定は新しい試合として扱う。

相手チームが一度リードした場合、その間に投げて既に退いた投手は勝投手候補から除外される。

### 先発投手の勝利資格

先発投手は、勝チームの守備イニング数に応じて次の回数を完了していなければ勝投手になれない。

- 勝チームの守備が6回以上の試合: 5回完了
- 勝チームの守備が5回で終わる試合: 4回完了

### 先発投手が勝利資格を満たさない場合

救援投手が1人だけなら、その救援投手が勝投手候補となる。

救援投手が2人以上いる場合は、勝利をもたらすのに最も効果的な投球をした救援投手が勝投手候補となる。

効果判定では次を考慮する。

- 投球回
- 失点
- 自責点
- 得点させた走者数
- 登板時の試合状況

同程度に効果的なら、先に登板した投手を優先する。

### 短く効果的でない救援投手

救援投手が短い登板で効果的でなく、後続投手がリード維持に効果的だった場合、前者ではなく後続の最も効果的な投手を勝投手候補とする。

一般的には、1イニング未満で2点以上を許した救援投手は「短く効果的でない」候補とみなす。ただし、これは記録員判断であり絶対条件ではない。

## 敗投手

自己の責任による失点で相手チームにリードを許し、そのリードが最後まで保たれた場合、その投手が敗投手となる。

同点になった時点で、敗投手の判定は新しい試合として扱う。

アプリ実装では、最終的な勝利チームが最後に勝ち越した得点を特定し、その得点の責任投手を敗投手候補とする。

## セーブ

セーブは救援投手に与えられる。

次のすべてを満たす必要がある。

- 自チームが勝った試合の最後を投げ切った
- 勝投手ではない
- 最低1/3イニングを記録した
- 次のいずれかに該当する

条件A:

- 3点以内のリードで登板し、最低1イニング投げた

条件B:

- 同点となる可能性のある走者、打者、または次打者がいる状況で登板し、リードを守り切った

条件C:

- 最低3イニング投げた

## ホールド

NPBのホールドは、救援投手で、勝利・敗北・セーブ・引き分けの記録を得なかった投手が対象となる。

次のいずれかを満たす場合にホールド候補となる。

条件A:

- セーブ条件を満たす状況で登板
- 1アウト以上を取る
- リードを保ったまま降板

条件B:

- 同点時に登板
- 1アウト以上を取る
- 登板以降、前任投手の残した走者を含め無失点で降板
- ただし、自チームが得点してリードした後は、失点してもリードを保っていればよい

補足:

- 走者を残して降板し、その走者が後任投手によって得点して同点またはビハインドになった場合はホールドを与えない

## アプリ実装メモ

### 必要データ

- 各半イニング開始時・終了時のスコア
- 各投手スティント
- 投手の登板開始時点のスコア、アウト、走者
- 投手の降板時点のスコア、アウト、走者
- 各得点の責任投手
- 最終勝利チーム
- 試合成立状態

### 自動算定しやすいもの

- 敗投手候補
- セーブ候補
- 先発投手の勝利資格
- ホールド候補の一部

### 記録員判断が必要なもの

- 先発投手が勝利資格を満たさない場合の、複数救援投手からの勝投手選定
- 短く効果的でない救援投手を勝投手から除外するか
- 試合の流れにおける「決定的なアウト」の評価

### 推奨UI

試合確定時に次を表示する。

- 自動候補
- 候補理由
- 代替候補
- 手動修正ボタン
- 確定後の `winningPitcherId` / `losingPitcherId` / `savePitcherId` / `holdPitcherIds`

### 現行の確定フロー

`pending_confirm` の試合を確定する時点で、勝敗が付く試合かつ投手候補が存在する場合は、投手勝敗確認モーダルを表示する。

現行実装は受け皿の第一段階として、登板履歴・守備位置・投手統計から候補を抽出し、記録員が勝利投手・敗戦投手・セーブ・ホールドを選択する。

保存先は `game.pitchingDecisions`。

```js
{
  winningPitcherId,
  losingPitcherId,
  savePitcherId,
  holdPitcherIds,
  confirmedAt,
  method: 'manual-confirmation'
}
```

今後の自動算定AIは、この画面に候補理由と推奨順位を追加する。
