# YouTube動画連動シミュレーション 操作密度ルール

## 目的

YouTube動画を見ながら記録する場合に、記録操作が人間にとって現実的かを判定する。

このルールは、記録の正誤ではなく、リアルタイム運用の実用性を評価する。

## 基本単位

操作密度は、動画時刻を基準に10秒単位で集計する。

対象操作:

- ボール/ストライク/ファウル等の投球記録
- 打席結果の選択
- 走者進塁の指定
- エラー、自責点、責任投手などの追加指定
- 投手交代、代打、代走、守備変更
- 動画時刻メモ
- モーダル確定、戻る、修正など記録完了に必要な操作

対象外:

- 動画の再生、停止、巻き戻し
- 画面スクロール
- 単なる確認視線移動

## 未対応プレーの判定

動画内で発生したプレーに対して、アプリ上に対応するボタン操作または進行手段がなく、記録を前に進められない場合は、操作密度に関係なくP1とする。

未対応プレーは次を残して報告する。

- 動画時刻
- イニング/表裏
- 記録粒度、記録レベル、記録環境
- 選択しようとしたプレー種別
- どの画面またはモーダルで前に進めなくなったか

## 10秒操作密度の判定

| 10秒あたりの操作数 | 判定 | 意味 |
|---:|---|---|
| 1-3 | リアルタイム記録可能 | 通常運用で対応できる |
| 4-6 | 慣れれば可能 | 一時停止なしでも可能性はあるが、ミスリスクあり |
| 7-10 | リアルタイム記録は厳しい | 一時停止・巻き戻し前提が望ましい |
| 11以上 | 非現実的 | UI改善または記録粒度の変更が必要 |

## モード別の許容目安

半イニングごと:

- 10秒あたり3操作以内が望ましい
- 走者やアウトの詳細を追わないため、高密度場面でも比較的実用的

打者ごと:

- 10秒あたり6操作以内が望ましい
- 連続プレー、走者進塁、エラー絡みでは一時停止推奨

1球ごと:

- 10秒あたり6操作以内が通常運用の上限
- 7操作以上が連続する場合は、リアルタイムではなく後追い記録向き

## 高密度場面の重点チェック

次の場面は、操作密度が急増しやすいため必ず監査する。

- 盗塁、暴投、捕逸、ボークなど投球と走者進塁が同時に起きる場面
- エラー付きの安打/凡打
- 複数走者の進塁と得点
- 打席途中の投手交代
- 代打/代走後の守備位置確定
- DH解除や投手が打順に入る場面
- 試合終了直後の勝敗投手・セーブ・ホールド確定

## 報告形式

操作密度監査では、最低限次を報告する。

```md
## 最大密度区間

- 動画時刻:
- 10秒操作数:
- 操作内容:
- 判定:

## 実用性

- リアルタイム記録:
- 一時停止前提:
- 推奨記録粒度:

## 改善候補

- 操作削減:
- UI統合:
- 自動補完:
```

## 改善提案の優先度

P1:

- 未対応プレーに対応するボタン操作がなく、記録を前に進められない
- 10秒あたり11操作以上
- 1プレー完了に10操作以上
- 入力中に次の投球/プレーが進む可能性が高い

P2:

- 10秒あたり7-10操作
- 複数モーダルをまたぐ操作が必要
- 同じ情報を複数回入力している

P3:

- 10秒あたり4-6操作
- 慣れで対応可能だが、ショートカットやプリセットで改善できる
