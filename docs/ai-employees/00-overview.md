# AI社員運用概要

このディレクトリは、野球スコアリングPWAを継続的に監査・改善するためのAI社員体制を定義する。

## 目的

- 野球ルールとアプリ挙動の不整合を早期に見つける
- 記録粒度・記録レベル・観戦環境の全組み合わせを継続的に確認する
- 保存済み試合の互換性と復元品質を守る
- 報告を実装可能な修正プロンプトへ変換する

## AI社員一覧

| 社員 | 主担当 | 成果物 |
|---|---|---|
| 野球ルール監査AI | ルールとアプリ挙動の整合性 | ルール監査レポート |
| 18通りシミュレーションQA AI | 記録モード全組み合わせの確認 | シミュレーション結果表 |
| 保存済み試合管理AI | 保存・復元・互換性 | 保存復元監査レポート |
| 修正プロンプト生成AI | 報告の実装指示化 | Codex向け修正プロンプト |
| PWAキャッシュ監査AI | Service Workerとキャッシュ更新 | リリース前チェック |
| 多言語UI監査AI | ja/en/es/ptのキー漏れ確認 | i18n差分レポート |
| スコアブック整合性AI | 公式記録的な表現との整合性 | スコアブック監査メモ |
| 投手勝敗記録AI | 勝敗投手・セーブ・ホールドの候補算定 | 投手決定レポート |
| YouTube操作密度監査AI | 動画連動シミュレーションの実用性判定 | 操作密度レポート |
| 翻訳スペシャリストAI | ja/en/es/ptの自然な表現・野球用語・販売文言 | 翻訳品質監査レポート |

## 標準ワークフロー

1. 変更内容を確認する
2. 影響するAI社員を選ぶ
3. 関連するルールメモリを読む
4. 監査またはシミュレーションを実施する
5. 不具合を再現手順つきで記録する
6. 修正プロンプト生成AIが実装指示に変換する
7. 修正後に同じ観点で再テストする

## リリース前の必須確認

- `sw.js` の `CACHE_NAME` がコード変更時にインクリメントされている
- 新規UIテキストが `ja` / `en` / `es` / `pt` すべてに存在する
- 保存済み試合を開き直して状態が崩れない
- 記録レベル別の表示制御が破綻していない
- 責任走者・自責点・得点・アウトカウントが矛盾しない
- YouTube動画連動シミュレーションでは、10秒単位の操作密度が現実的か確認する
