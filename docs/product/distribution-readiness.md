# 配布準備とアプリ化判断

## 方針

最初はPWAのままモニター募集と小規模販売検証を行う。

本物のネイティブアプリ化、またはストア配布は、1試合通し検証で致命的な不具合がなくなり、問い合わせや購入意欲が見えてから判断する。

## モニター/購入者に使ってもらうための必須設定

| 領域 | 必須項目 | 判定 |
|---|---|---|
| 公開URL | HTTPSでアクセスできるURLがある。 | 未設定なら配布不可。 |
| PWA | `manifest.json` の名前、アイコン、表示モード、テーマカラーが意図通り。 | `docs/pwa/release-checklist.md` で確認。 |
| Service Worker | `sw.js` が有効で、主要ファイルがキャッシュされる。 | Chrome DevToolsで確認。 |
| オフライン | トップ画面、試合開始、最低限の記録操作がオフラインで使える。 | 実機で確認。 |
| 保存/復元 | 保存済み試合を再読み込み後に復元できる。 | 実戦前に確認。 |
| インストール案内 | iPhone Safari / Android Chrome / PC Chrome の手順がある。 | `docs/pwa/install-guide.md` を使う。 |
| 不具合報告 | フォームまたはWhatsAppで報告できる。 | 配布前にリンクを用意。 |
| サポート | WhatsApp Business の問い合わせ先がある。 | モニター募集文に入れる。 |
| 共有 | 試合結果をWhatsAppへ送れるテキストまたは共有導線がある。 | 販売前に最低限のTXT共有を用意。 |
| プライバシー | 端末保存、同期なし、ブラウザデータ削除時のリスクを説明できる。 | `docs/privacy/data-storage.md` を使う。 |
| 既知の制約 | モニター版であること、記録ミスの可能性を明記する。 | 募集文と案内ページに入れる。 |

## 配布ページに必要な要素

- アプリ名
- 対象ユーザー
- 何ができるか
- モニター版であること
- アプリURL
- PWAインストール手順
- 1試合通し検証のお願い
- データ保存の注意
- 不具合報告フォーム
- WhatsApp問い合わせリンク
- WhatsApp共有の使い方
- 対応言語
- 既知の制約

## 公開前チェック

1. `docs/pwa/release-checklist.md` を使ってPWA基本項目を確認する。
2. `docs/privacy/data-storage.md` の説明を配布ページに反映する。
3. iPhone Safariでホーム画面追加を試す。
4. Android Chromeでインストールまたはホーム画面追加を試す。
5. オフライン状態で起動と最低限の記録を試す。
6. 保存済み試合をリロード後に復元する。
7. フィードバックフォームの送信テストをする。
8. WhatsApp Businessの問い合わせリンクを開く。
9. 試合結果共有テキストをWhatsAppへ送れるか確認する。
10. モニター募集文からアプリURL、フォーム、WhatsAppへ迷わず進めるか確認する。

## PWAのまま売るメリット

- URLをWhatsAppやFacebookで直接渡せる。
- ストア審査を待たずに改善を反映できる。
- 南米日系コミュニティへの小規模検証に向く。
- ユーザー登録なしで試しやすい。
- App Store / Google Play の準備コストを後回しにできる。
- オフライン、軽量、多言語という既存の差別化と合う。

## PWAのまま売る弱点

- App Store / Google Play の検索流入を使えない。
- iPhoneではホーム画面追加の説明が必要。
- ユーザーが「本物のアプリではない」と感じる可能性がある。
- ストアレビュー、ランキング、アプリ内課金の導線が使いにくい。
- ブラウザデータ削除で保存済み試合が消えるリスクを説明する必要がある。

## ネイティブアプリ/ストア配布を検討する条件

| 条件 | 判断 |
|---|---|
| 20から30試合分の実戦検証でP0/P1がほぼ消えた。 | アプリ化検討可。 |
| WhatsApp問い合わせや購入意欲が複数出た。 | Android先行を検討。 |
| PWA追加手順でモニターが多くつまずく。 | ストア配布の価値が上がる。 |
| 共有、通知、クラウド同期、チーム管理が必要になった。 | ネイティブ/ストア化の価値が上がる。 |
| iOSユーザーの有料需要が強い。 | Apple Developer ProgramとApp Store審査を検討。 |

## 推奨ロードマップ

| フェーズ | 配布形態 | 目的 |
|---|---|---|
| 1 | PWA限定モニター | 1試合通し検証、不具合発見、操作改善。 |
| 2 | PWA小規模販売 | WhatsApp問い合わせ、導入相談、購入意欲確認。 |
| 3 | Androidストア検討 | Google Playで信頼性と導入しやすさを補強。 |
| 4 | iOSストア検討 | 有料化、継続利用、iPhone需要が見えてから進める。 |

## Android化の方向性

Androidは、PWAをTrusted Web ActivityなどでラップしてGoogle Playに出す選択肢がある。

初期検討で確認すること:

- Google Play Console アカウント
- アプリアイコン、スクリーンショット、説明文
- プライバシーポリシーURL
- PWAとアプリのURL関係
- ストア審査に耐える品質
- 有料化する場合の決済方針

## iOS化の方向性

iOSはApp Store審査とApple Developer Programが前提になる。

初期検討で確認すること:

- Apple Developer Program
- App Store Connect のメタデータ
- プライバシー説明
- スクリーンショット
- 審査で「単なるWebView」と見なされないだけの価値
- iOS実機での保存、オフライン、表示品質

## 現時点の判断

現時点ではPWAのまま進める。

理由:

- まだ1試合通し検証が不足している。
- 南米日系人向けはWhatsAppとFacebook経由のURL配布と相性が良い。
- 不具合修正と翻訳改善を高速に回す段階である。
- ストア化は信頼性と需要が見えた後の強化策にした方がよい。

## 次アクション

1. モニター募集ページまたは投稿を用意する。
2. フィードバックフォームを作る。
3. PWA配布URLとWhatsApp Businessリンクを決める。
4. 5試合分の通し検証を集める。
5. P0/P1を修正する。
6. PWA小規模販売投稿を `ready_for_manus` にする。
