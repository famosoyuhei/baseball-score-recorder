# 東東京予選 観戦フィールドテスト

## 前提

対象日: 2026-07-17

目的は、外部モニター募集前に、観戦しながら1試合を通してアプリを使えるか確認すること。正式販売や外部告知ではなく、セルフ実戦テストとして扱う。

## 試合前チェック

| 確認 | 内容 | メモ |
|---|---|---|
| アプリURL | スマホで開けるURLを用意する。 | 公開URL未確定ならPCローカル検証を先に行う。 |
| バッテリー | スマホの充電、モバイルバッテリー。 | 試合中に画面を長く使う。 |
| ブラウザ | iPhoneならSafari、AndroidならChrome。 | PWA検証と合わせる。 |
| ホーム画面追加 | 可能なら試合前に追加する。 | 球場で迷わないため。 |
| 通信 | 球場で通信が弱い可能性を前提にする。 | オフライン起動を確認できるとよい。 |
| 記録方針 | まずは `bench` モード、`batter` レベル推奨。 | 迷ったら簡単な設定を優先。 |
| メモ手段 | 紙メモまたはスマホメモを用意。 | アプリが止まった時の状況記録用。 |

## 推奨設定

| 項目 | 推奨 | 理由 |
|---|---|---|
| 記録環境 | `bench` | 観戦中でも入力負荷を抑えやすい。 |
| 記録レベル | `batter` | 1打席単位で実戦の穴を見つけやすい。 |
| 選手詳細 | 最小限 | 初回は選手名入力で疲れすぎないようにする。 |
| チーム名 | 実名または仮名 | 個人情報を残したくない場合は仮名にする。 |

## 試合中に必ず確認すること

- 試合を開始できるか。
- 得点、アウト、走者が画面上で追えるか。
- 安打、四球、三振、アウト、エラー相当の入力で迷わないか。
- 走者の進塁を直感的に扱えるか。
- 3アウトで攻守交代できるか。
- イニング表示とスコア表示が直感と合うか。
- 保存ボタンを押してエラーが出ないか。
- 画面を閉じる/再読み込みした後に復元できるか。
- 通信が弱くなってもトップ画面または記録画面を開けるか。

```text
打者:

期待した結果:

```

## 途中でアプリが厳しくなった時の逃げ道

- 試合全体の完全記録にこだわらない。
- 迷った場面をメモし、次の打席から再開する。
- 得点、アウト、走者だけでも追う。
- 保存/復元の確認だけはできるだけ行う。
- 不具合再現のために、スクリーンショットを残す。

## 試合後チェック

| 確認 | 内容 |
|---|---|
| 保存 | 試合終了後に保存できたか。 |
| 復元 | ページ再読み込み後に試合を開けるか。 |
| スコア | 最終スコアが実際と一致しているか。 |
| 操作負荷 | 観戦しながら入力し続けられる負荷だったか。 |
| 記録不能 | 記録できなかったプレーがあったか。 |
| 改善案 | 次に直すべきUI/説明は何か。 |
